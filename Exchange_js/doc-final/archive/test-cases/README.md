## 1. 断言口径（最重要）

**用例的预期结果一律按 PRD 的「应然」写，不按代码现值写。**

PRD 里已自曝一批「应然 ≠ 代码」的漂移点（审计事件名、记账 eventCode、五桶枚举名等）。这类用例在「备注」列打 `⚠漂移` 并写明代码现值——**跑出来红是正常的，它指向的是代码待对齐，不是用例写错**。若把预期改成代码现值，用例就失去验收意义，只剩回归意义。

需要一份「当前版本应全绿」的回归集时，另建 `regression/` 子集，不要就地改本目录的预期值。

## 2. 范围界定

### 覆盖

- 各 PRD **模块 7「验收标准」的全部 AC**（约 105 条）
- 模块 5 的 **FR / 状态机跃迁表 / 判定决策表** 逐行补边界与反例
- 正文范围内的 **fail-closed 拒绝断言**（如守卫拒绝、非法跳步拒绝、报价过期拒绝）——这些写在 PRD 正文里，属 happy path 文档的组成部分

### 不覆盖（本轮明确排除）

| 排除项 | 依据 |
|---|---|
| 充值附录 B/C、提现附录 B/C 的 **Sumsub 异常状态机**（FROZEN / ACTION_PENDING / MANUAL_CHECKING / SEIZED / RETURN_TO_SENDER / REJECT_REFUND 等） | 正文模块 6 明确列为非目标，另篇再写 |
| 提现 **大额审批门**（≥200,000 AED → SMO）、失败/解锁路径（FAILED / releaseLock / admin 拒·取消·复核） | 提现 PRD 非目标 1、2 |
| 充值 **异常分支**（冻结/拒绝/补材料/失败/过期/没收） | 充值 PRD 非目标 1 |
| 各 PRD 模块 8 标 **⬜ / G 的已知缺口**：账本 G1（onboarding 建客户账户）、钱包 G3/G4（原地重试·同址重提）、对账 G1/G2/G4/G5（人工强推·破账处置·AWAITING·状态结转）、兑换 G2（过期报价 cron） | PRD 自述「无验收」 |
| 演示脚手架（资金单 advance 模拟推进） | 资金单 PRD 非目标 5 |
| DDL / API 出入参 / 错误码 / 索引 | 各 PRD 统一交开发 |

> **注**：Sumsub KYT/TR 真实集成未做（充值 G3 / 提现 G1），但相关 AC 在 PRD 正文里有验收——用例照写，步骤中注明「经模拟端点注入合规结果」作为触发方式。

**字段**：

| 字段 | 说明 |
|---|---|
| ID | 用例唯一编号 |
| 锚点 | 回指 PRD 的 AC / FR / 状态机跃迁号 / 判定表行——**每条用例必须可追溯到 PRD 某一行** |
| 类型 | `正例`（主路径）/ `反例`（应被拒绝）/ `边界`（阈值恰命中·恰差一） |
| P | 优先级，见下 |
| 前置 | 执行前必须成立的状态 |
| 步骤 | ①②③ 紧凑编号 |
| 预期 | 可判定的断言（含具体数值/状态值/事件名），禁止「正常显示」这类不可判定表述 |
| 备注 | `⚠漂移` = 与代码现值不符；触发方式说明；数据构造提示 |

**优先级**：

| P | 含义 | 判据 |
|---|---|---|
| P0 | 资金安全 / 不变量 / fail-closed 守卫 | 错了会丢钱、破账、或放行不合规主体 |
| P1 | 主链路功能与状态机正确性 | 错了功能不可用，但不直接损失资金 |
| P2 | 读面 / 可解释性 / 展示 | 错了影响运营效率 |

## 5. 维护规则

1. **PRD 改 → 用例同步**：AC 增删改必须回到本目录改对应用例，锚点断链视为缺陷。
2. **缺口兑现 → 补用例**：PRD 模块 8 的 G 项一旦落地，从上方「不覆盖」表移除并补用例。
3. **漂移消除 → 摘标记**：代码与 PRD 对齐后，删掉该用例的 `⚠漂移` 备注。
4. 用例只增不改语义：已执行过的用例若断言需变更，新开一条并注明取代关系。
