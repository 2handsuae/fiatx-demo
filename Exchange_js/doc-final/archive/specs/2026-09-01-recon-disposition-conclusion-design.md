## §0 定调：四条公理（业主 2026-09-01 立）

1. **对账的外部资料是权威，不会错。** 推论：没有「对方错了」这一档——一切不平只有三种性质：我方账**错了** / 我方账**缺了** / **时机没到**。旧种子里贴着「对方错」标签的三个场景（银行漏报③ / 对账单重复行⑨ / 对方金额记错⑩）经代码实证全是同构贴错标签（③≡⑧、⑨≡⑤、⑩≡④——它们都动了外部收盘余额，动了收盘就等于宣布"银行那边真是这个数"），删两条、改一条标签。
2. **屏幕上所有不平就是 6 格**：三种不平类型（金额不对 / 我有外无 / 外有我无）× 两个池子（客户 / 公司）。机器只知道格子，不知道成因。
3. **成因是表象背后的东西，要财务去查才知道。** 15 个成因里只有一个机器认得出（重复入账的同参考号双胞胎，实跑数据核过），其余全靠人。系统的责任是把查证结论收下来、存下来、并据此给出口。
4. **处置是行业公认的动词集，几乎不变**：推单、冲正、冲销、补记、改记、挂起、补单、核销、豁免、事故升级。

### §0.1 为什么核销 / 豁免不挂在任何具体原因后面

因为它们挂在**查证结果轴**上，不挂在业务原因上（银行对账业内标准做法）：

```
财务查证一条差异
 ├─ 查明了原因 ────────────→ 成因注册表（§4）→ 各自的处置
 ├─ 查明了，但永远修不了 ────→ 豁免（永久调节项，不动账）
 └─ 查不出（调查穷尽）──────→ 挂起·调查中
                              └─ 账龄到线 → 小额：核销（差额进损益，动账结案）
                                          → 大额：升级为事故
```

- **账龄（aging）是核销的前置**：没有账龄线，查无果的案子永远躺在调查中，核销没有触发时机。故核销/豁免与 aging 同批做（下一轮）；本轮建到「挂起·调查中」为止——它是核销的前半段，查证记录都留好。
- **核销两个池子做法不同**：公司池一笔分录差额进损益；客户池必须两步——认损调账 + 公司真金白银补款（decisions [2026-08-28]「客户侧公司承担没有账面捷径」）。
- **容差是豁免的事前自动版**（低于阈值不开案），豁免是事后人工版；同批设计。

### §0.2 上一版为什么作废（一句话存档）

2026-08-29 版用「形状 × 账簿 → 动作」判定表分派按钮；但同形状的行成因可以相反（展示位的全部意义），按形状分派必然给同形状的行同一个按钮，且会给「不该动账」的行一个动账按钮。根因：15 个成因进门时塌缩成 6 格，信息在那一刻已丢，机器达不到那个目标。本版把「补回丢失信息」这一步显式交给人（选成因），机器只做成因之后的可判定部分。

### §0.3 讨论确立的口径（结论，不要翻案）

| 结论 | 依据 |
|---|---|
| 同形状的行给同一个「处置」按钮，差异化发生在人选完成因之后 | 公理 2、3 |
| **第一屏 = 从该格的成因菜单里选成因**，成因 → 处置自动定 | 业主 2026-09-01 拍板（取代「三选一定性」）；财务查证的产物是成因，不是哲学立场 |
| 成因码注册表**单一来源**：财务手册、界面菜单、审计记录三处同码 | 防止手册一套词、界面一套词 |
| 「我记 35、外部 35.02，钱都收到了」是**冲正**，不是豁免也不是核销 | 业主裁定；外部权威 + 钱在，就该改成 35.02 |
| 手续费由公司承担、不从客户钱包走，decisions [2026-08-28] **不变** | 业主 2026-09-01 重申（此前一度改判又撤回）；场景 5 轧差按「我方错·冲正」处置，公司补款给客户属二期内部划转，演示词带一句 |
| 本轮处置覆盖：**推单、冲正、冲销、补记、挂起、改记**；补单、核销、豁免下一轮；事故三期 | 业主 2026-09-01 拍板 |
| 改记 = 调账单第四族，不另立主体 | 纯账本纠错、无资金单、无在途，符合 decisions [2026-08-28]「调账不是订单」 |
| 查无果场景铺在**公司池** | 为下一轮核销留单笔分录的干净落点，不背客户池两步复杂度 |
| 演示种子**按处置铺，不按原因铺** | 同处置的不同原因屏幕上不可区分，铺多条是浪费；完整原因枚举活在手册里 |
| 挂起不让案子变绿 | 差异还在，只是知道了原因；第六幕不粉饰 |
| 本轮零引擎改动 | 残差公式、五桶规则、销案判据一律不碰 |

## §2 处置全集（应然十件）与本轮覆盖

| 处置 | 定义一句话 | 动账 | 本轮 |
|---|---|---|---|
| 推单 | 钱在路上，把资金单推到终点 | 否（走原流程记账） | ✅ 已有 |
| 冲正 | 事情真发生了，把我方记错的金额改成对的 | ✅ 差额一笔分录 | ✅ 已有，接定性流 |
| 冲销 | 我方记了一笔外面根本没发生的，撤掉 | ✅ 整笔反向分录 | ✅ 已有，接定性流 |
| 补记 | 外面真发生了一笔公司收支，我方补上 | ✅ 整笔分录 | ✅ 已有，接定性流 |
| **改记** | 钱没动，主人记错了，从 A 名下改到 B 名下 | ✅ 应付对转，资产腿不动 | 🔨 本轮新建 |
| **挂起** | 查证结论=我方账不动（等下期自平 / 调查中） | ❌ | 🔨 本轮新建 |
| 补单 | 钱真进出了，回业务域把流程真跑一遍（进→充值补录，出→退汇认领） | 走业务流程 | ⏭ 下一轮（本轮留档指路） |
| 核销 | 查不出+挂太久+金额小，差额进损益结案 | ✅ | ⏭ 下一轮（与 aging 同批） |
| 豁免 | 查明了但永远修不了，挂永久调节项 | ❌ | ⏭ 下一轮（与容差同批） |
| 事故升级 | 未授权转出等：登记、定性、升级、通报 | 治理件 | ⏭ 三期 |

## §3 两屏交互

### §3.1 差异行动作位六态

| 行态 | 显示 |
|---|---|
| 已匹配 | 空 |
| 在途 | `去推单 →`（链资金单页） |
| 差异 · 未定性 | `处置` 按钮（权限控显隐，非禁用态；案件非 OPEN 不给） |
| 已定性 · 待开单 | 徽标 `已定性 · <成因> → <处置>` + `开单` 按钮（仅 ADJUST 类出口；持调账写权者可见） |
| 已定性 · 终态 | 徽标 `已定性 · <成因> → 挂起/留档 · <人> <日期>`（点开看查证说明；未挂单前可覆盖重定） |
| 已解释 | `已解释 · ADJxxx` 链接（现状不变） |

### §3.2 第一屏 · 选成因

菜单 = 该格（形状 × 账簿）在成因注册表里的清单，机器只出线索不出结论：

```
处置 · WA2601014255 · AED · 我有外无 · 7,300.00
─────────────────────────────────────────────
这条差异查下来的成因是？
 ( ) 重复入账——同一笔入了两次            → 冲销
 ( ) 假信号入账——外部凭证不存在          → 冲销
 ( ) 提现已记但银行未执行                → 冲销
 ( ) 记错客户——这笔钱是别人的            → 改记
 ( ) 跨账期——下期自平                    → 挂起
 ( ) 查不出——已穷尽调查                  → 挂起·调查中
 💡 机器线索：已匹配列表有同参考号同金额行
    （ZB…9F236B）——指向「重复入账」
─────────────────────────────────────────────
查证说明（必填）：[____________________]
                                [下一步 →]
```

- 成因**必选、无兜底档**（「查不出」不是兜底——它要求说明里写清查过什么）
- **机器线索**只在证据命中时出现（本轮唯一一条：该 `ORPHAN_INTERNAL` 行的 `externalRef` 在同案件**已匹配行**里同额出现），不出现时无占位
- 保存定性即记审计；同锚重定 = 覆盖 + 再记一条审计；已挂调账单的行拒绝覆盖（400）

### §3.3 第二屏 · 按出口分四种

| 出口 | 第二屏 |
|---|---|
| 冲正 / 冲销 / 补记 | 内联调账单表单：金额预填、**方向只读**（附一句推导依据）、成因码已由注册表派生（不给下拉）、生效日=案件业务日、客户加钱必填关联原单号、两版理由 → 提交 = 定性 + 调账单草稿一起落，送审 |
| 改记 | 对端选择：机器给候选清单（同业务日 · 同资产 · 同金额 · **反向孤儿**的开放案件），确认 → 改记单送审 |
| 挂起（两子类） | 确认页（明示「不落任何分录」）→ 保存即完 |
| 留档待开 | 说明页：该去哪（充值补录 / 退汇认领 / 公司冲销 / 事故 / 豁免）+「下一轮开放」→ 保存定性，案子继续红 |

**角色交接**（定性与开单是两个人，界面按权限自然切分）：运营定性（第一屏保存即止，行进入「已定性 · 待开单」）→ 金库在该行看到 `开单` 按钮，点开进第二屏表单 → 运营审批。演示用超管一人走通不受影响。

方向推导规则（统一口径 `差额 = 外部 − 内部`）：

| 形状 | 推导 |
|---|---|
| 金额不对 | 差额符号：负 → 减，正 → 加 |
| 我有外无 | 内部流水方向取反：IN → 减，OUT → 加 |
| 外有我无 | 外部流水方向照搬：IN → 加，OUT → 减 |

案件列表加一列**定性进度**（`3/5`：已定性差异行 / 总差异行）。

## §4 成因注册表（单一来源）

新常量文件 `disposition/cause-registry.ts`。每条：`causeCode`、所属格、菜单文案、查证线索、出口（含 ADJUST 的族与 reason 派生、留档的去向标签）。财务手册（§10）与界面菜单都从这份注册表出词，审计记录存同一个码。

### 金额不对 × 客户

| 成因码 | 菜单文案 | 查证线索 | 出口 |
|---|---|---|---|
| `AMT_MISBOOKED` | 我方金额录错（含小数点错位、少记） | 对银行回单原件，差额无规律 | 冲正 |
| `AMT_FEE_NETTED` | 银行轧差入账（手续费被扣净额） | 差额恰为固定费/费率，同通道笔笔如此 | 冲正（公司补款给客户属二期，演示词带一句） |
| `AMT_ROUNDING` | 舍入精度差（钱已到位） | 差额在最小精度量级 | 冲正 |
| `PRECISION_DUST` | 精度不可表示的尘埃差 | 差额低于我方最小记账单位 | 留档 · 豁免（下一轮） |
| `UNEXPLAINED` | 查不出（已穷尽调查） | 说明里写清查过什么 | 挂起 · 调查中 |

### 金额不对 × 公司

| 成因码 | 菜单文案 | 出口 |
|---|---|---|
| `FIRM_AMT_UNDERBOOKED` | 公司收支记少（实扣/实收 > 所记） | 补记差额（支出差→银行杂费，收入差→银行利息） |
| `FIRM_AMT_OVERBOOKED` | 公司收支记多 | 留档 · 公司冲销无码（下一轮补码） |
| `PRECISION_DUST` | 精度尘埃 | 留档 · 豁免（下一轮） |
| `UNEXPLAINED` | 查不出 | 挂起 · 调查中 |

### 我有外无 × 客户

| 成因码 | 菜单文案 | 查证线索 | 出口 |
|---|---|---|---|
| `DUP_BOOKING` | 重复入账——同一笔入了两次 | **机器线索**：已匹配行里同 ref 同额双胞胎 | 冲销（重复入账撤销） |

| `PAYOUT_NOT_EXECUTED` | 提现已记但银行未执行 | 无回执/有失败通知 | 冲销（提现撤销退回，余额加回） |
| `MISATTRIBUTED_FROM` | 记错客户——这笔钱是别人的 | 对端钱包同日同额「外有我无」成对 | **改记** |
| `CUTOFF_STRADDLE` | 跨账期——下期自平 | 外部行时间戳落下一账期，余额并不差 | 挂起 · 等下期 |
| `UNEXPLAINED` | 查不出 | — | 挂起 · 调查中 |

### 我有外无 × 公司

| 成因码 | 菜单文案 | 出口 |
|---|---|---|
| `FIRM_MISBOOKED` | 公司收支误记/重复记 | 留档 · 公司冲销无码（下一轮） |
| `FIRM_TRANSFER_UNTRACKED` | 公司调拨已记账、无资金单跟踪 | 留档 · 二期内部划转（本不该发生） |
| `UNEXPLAINED` | 查不出 | 挂起 · 调查中 |

### 外有我无 × 客户

| 成因码 | 菜单文案 | 出口 |
|---|---|---|
| `MISSED_DEPOSIT` | 漏记客户入金 | 留档 · **补单→充值域补录**（下一轮） |
| `BOUNCED_FUNDS` | 入金被退汇/回冲 | 留档 · **补单→退汇认领**（下一轮） |
| `MISATTRIBUTED_TO` | 记错客户——这笔是本客户的、记在了别人名下 | **改记** |
| `UNAUTHORIZED_OUTFLOW` | 未授权转出（盗转/误划） | 留档 · 事故升级（三期） |
| `UNEXPLAINED` | 查不出 | 挂起 · 调查中 |

### 外有我无 × 公司

| 成因码 | 菜单文案 | 出口 |
|---|---|---|
| `BANK_INTEREST_UNBOOKED` | 银行利息未入账 | 补记（银行利息） |
| `BANK_CHARGE_UNBOOKED` | 银行杂费/账管费未入账 | 补记（银行杂费） |
| `UNCLAIMED_INFLOW` | 无主入金待归属 | 挂起 · 调查中（查归属；查明是客户→转补单，查明是公司→补记） |
| `UNEXPLAINED` | 查不出 | 挂起 · 调查中 |

**调账 reason 派生规则**（第二屏不再让人选 reason）：

- 冲正类成因 → 按该行内部流水 `sourceType`：DEPOSIT → 充值金额更正，WITHDRAW → 提现金额更正；**其他 sourceType 本轮无码 → 留档待开**（边界，SWAP 流水的金额差演示无此案）
- `DUP_BOOKING` → 重复入账撤销 ｜ `PHANTOM_BOOKING` → 充值撤销 ｜ `PAYOUT_NOT_EXECUTED` → 提现撤销退回
- `FIRM_AMT_UNDERBOOKED` → 按差额方向：支出差 → 银行杂费，收入差 → 银行利息 ｜ `BANK_*_UNBOOKED` → 对应码
- `MISATTRIBUTED_FROM / _TO` → 新第 8 码 `CUSTOMER_REATTRIBUTION`（第四族）

手册另收「历史遗留尾差」（`LEGACY_RESIDUAL` → 豁免/一次性核销，下一轮）为脚注，不进本轮菜单。

## §6 改记（调账单第四族 REATTRIBUTE）

**语义**：钱在托管里一分没动，我方把主人记错了。把一笔已入账的钱从错记方名下改到正主名下。

- **分录（第五种组合）**：借 错记方 `CLIENT_PAYABLE` / 贷 正主方 `CLIENT_PAYABLE`——**客户资产腿不动**。现有四种组合（账簿 × 方向）覆盖不了它，故成因码 `CUSTOMER_REATTRIBUTION` 单列一族，分录由族直接定，不走 book × direction 语义
- **一张单、两个锚、双案同愈**：现有两个锚字段正好一边一个——`explainedFlowId` 锚错记方的内部流水（我有外无行）、`explainedExternalLineId` 锚正主方的外部行（外有我无行）。落账后两条差异行各自标已解释；重对账跑该业务日会覆盖全部钱包，一次重跑两案同 RESOLVED。⚠️ 实施时必须核实引擎的已解释摘除按**锚 id** 匹配、不按调账单的 walletRef/caseNo 圈定——若有圈定须放开到两侧（验收判据 2 兜底）
- **模型**：`ReconciliationAdjustment` 加 `toWalletRef` / `toOwnerNo`（仅第四族使用）；`book` 恒 CLIENT
- **守卫**：正主方是加钱 → **必填关联原单号**（记在错记方名下的那张真实充值单——KYT 对这笔钱跑过，放行依据与一期边界线同源）；两侧差异行**业务日必须相同**，不同则 400（跨日改记本轮不做）；生效日 = 该业务日
- **合规口径**（业主拍板）：换主靠「原单 KYT 已跑」放行，本轮不重跑 KYT；「换主后对正主的合规复核」登记 BACKLOG 一行
- **审批**：与三族相同（金库开单、运营复核）；审批页人话后果：「本单将把 7,300.00 AED 从客户 CUxxxx 名下改记到客户 CUyyyy 名下；客户资产总额不变」。走 `ApprovalsService` 正门、**复用既有 `RECON_ADJUSTMENT_POST` 策略不新增策略**——故 `verify-rbac` 的 `MAKER_GROUP_BY_POLICY` 表不加行（checklist「新增审批策略」未触发，显式记一笔免评审再查）
- **记账路径**：落账同步直调 `AccountingService.executeTransfer`（禁挂事件，失败即流程失败、状态不得推进）；两腿都是既有科目 `CLIENT_PAYABLE`，**不新增科目**；无资金单（纯纠错，无在途要追）
- **审计**：落账复用 `RECON_ADJUSTMENT_POSTED`（reasonCode = `CUSTOMER_REATTRIBUTION`）
- 对端候选清单与确认视图展示 `walletNo` / `customerNo`，不露 UUID（铁律⑥）
- **客户可见面**：错记方余额下降必须对其可见（客户流水三原则），随「客户流水读模型」任务做，本轮不动客户端

## §7 定性落库（数据模型）

```prisma
model ReconciliationDisposition {
  id                      String    @id @default(uuid())
  dispositionNo           String    @unique @default("TEMP")  // 业务键（铁律⑥）
  caseNo                  String
  walletRef               String
  businessDate            String
  // 锚：与调账单同款，锚真实证据 id，跨轮稳定；不锚每轮重建的 ReconciliationLineItem.id
  explainedFlowId         String?   // account_flows.id（我有外无 / 金额不对行）
  explainedExternalLineId String?   // external_statement_lines.id（外有我无 / 金额不对行）
  matchType               String    // 定性时的形状快照
  book                    String    // CLIENT | FIRM
  causeCode               String    // 成因注册表码
  outlet                  String    // ADJUST_CORRECT|ADJUST_REVERSE|ADJUST_RECORD|ADJUST_REATTRIBUTE|HOLD_NEXT_PERIOD|HOLD_INVESTIGATING|DEFERRED
  deferredTarget          String?   // outlet=DEFERRED 时的去向标签
  findingNote             String    // 必填查证说明
  adjustmentNo            String?   // ADJUST 类出口开单后回填；非空后禁止覆盖定性
  createdByUserId         String
  createdAt               DateTime  @default(now())
  updatedAt               DateTime  @updatedAt

  @@index([caseNo])
  @@index([walletRef, businessDate])
  @@map("reconciliation_dispositions")
}
```

同一条差异行（同锚）至多一条有效定性，重定 = 覆盖 + 各记一条审计；`adjustmentNo` 非空后拒绝覆盖（400）。

定性记录**没有状态机**（刻意）：覆盖式记录，唯一的锁就是 `adjustmentNo` 非空，不建迁移表。checklist「新状态要不要计时」显式回答：**本轮不计时**——查无果的账龄计时是核销的前置，归下一轮 aging（§0.1）。
