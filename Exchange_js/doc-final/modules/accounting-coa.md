## 0. 一句话定位

**账本是整个系统的事实层。** TigerBeetle 复式记账是余额的唯一真相——数据库里没有"余额字段"，只有凭证与流水投影。每笔交易就地逐腿记账（实时 1:1），没有日终轧差、没有延迟结算。

## 1. 业务叙事

最重要的一件事：**余额不是一个被改来改去的数字，是账本里借贷相抵的结果。** 想让客户余额变，唯一的办法是记一笔账——这就是"凭空造钱"在这个系统里做不到的原因。

**九个科目讲完全部家底。** 客户侧三个：客户资产池（钱的物理存放）、客户应付（欠客户的）、合规暂扣（进了门还没放行的）；公司侧六个：公司资产、运营、结算中转（仅法币）、三个收入户（兑换费 / 提现费 / 其他——没收入公司的钱归"其他"，与服务费隔离）。**科目是代码定义的，不做运营配置**（业主原则：科目表为系统服务，财务口径走报表视图，不预留号段）。

**两条恒等式是天平。** 客户侧：客户资产 = 客户应付 + 合规暂扣；公司侧：公司资产 = 运营 + 结算中转 + 三收入户之和。按币种各自守恒，随时可验。

**恒等式有个盲区，负余额断言补上。** 两侧同增同减的错账（凭空造余额、超额划扣）恒等式看不见——正负相消照样全绿。所以校验器额外遍历每个科目：**任何科目余额为负即失败**。这条断言首次实跑就逮到真实案例（测试直插中间态单把暂扣户扣成 −1e12，恒等式却全绿）。

**先锁后落。** 提现和充值的处置弧（没收/退回/上缴）都走两阶段：先锁定（挂起中的钱两边都看得见但谁也用不了）→ 结算落定或作废解锁。客户"可用余额" = 账面余额 − 锁定中金额。

**科目也有生死。** 旧的手续费/流动性/罚没三户已退役，由三个收入户接班——退役当日兼容层删净、数据重铺到终态（demo 重铺原则的教科书案例：不留迁移脚本、不留双写）。

## 2. 不变量（本域没有状态机，只有天平）

| 不变量 | 口径 |
|---|---|
| 客户侧恒等 | Σ客户资产 = Σ(客户应付 + 合规暂扣)，按币种 |
| 公司侧恒等 | Σ公司资产 = Σ(运营 + 结算中转 + 三收入户)，按币种 |
| 无负余额 | 任何 ACTIVE 科目按借贷方向算出的余额 ≥ 0 |
| 账户唯一 | (科目码, 币种, 归属类型, 归属人) 四元组唯一 |
| 验证入口 | `verify:coa`——两恒等式 + 负余额断言，秒级，动钱任务收尾闸⑦ |

## 3. 决策点与角色

- **科目增删 = 代码变更**，走发版评审，不是管理台操作；**手动建账**仅剩一个 admin 兜底端点（带审计）
- **记账失败 = 流程失败**（铁律 §5.5）：工作流同步直调记账，失败则业务状态不得推进——绝不把记账挂到事件上异步补
- 账本读面三页三权限分治：账户（实时余额）/ 凭证 / 流水（含每行过账后余额快照），只读为主

## 4. 演示脚本（账本视角，贯穿各幕）

1. 第三幕充值入账后 → 账本流水页看两步分录、每行"过账后余额"
2. 第四幕兑换成功后 → 凭证页看四腿、收入户里兑换费到账
3. 第五幕提现锁定期 → 账户页看客户可用余额与锁定的差
4. 第六幕开场 → 现场跑 `verify:coa` 全绿，讲两恒等式与负余额断言的分工
5. 任一凭证 → 点开看借贷双方科目、参考号、生效日——"每一分钱都有对手方"
