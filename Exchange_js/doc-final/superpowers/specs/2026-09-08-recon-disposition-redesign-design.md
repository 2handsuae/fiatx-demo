## 0. 一句话与责任模型

差异行上**直接放处置按钮**（按格出、按记账事实过滤）→ 点按钮出**一个弹窗**（原因码 + 单据字段 + 查证说明一次填完）→ 动钱的送 CFO 单步复核，挂起零账务直接落。「Record finding」两屏定性弹窗退役。

责任模型：**错误责任归财务，系统流程不担责**。系统只保留三样立场——硬边界（开不出的单不给按钮）、留痕（码 + reason 成对入审计）、复核（CFO）。选哪个处置是财务的判断，选错了 CFO 打回，审计里是谁的判断一目了然。原「人选成因、系统判出口」（decisions 2026-09-01）由本 spec 覆盖。

## 1. 业主拍板清单（2026-09-08，全部已定）

1. **乙档硬边界**：系统只过滤「账务上开不出单」的选项（规则全来自记账事实），合法集合内财务自选；丙档软建议明确不做。
2. **行上直接按钮**，替换 Record finding；六格按钮清单见 §2。
3. **一个弹窗涵盖处置 + 原因 + 字段**，提交即开单送审（挂起不送审）。
4. **单码制**：原 11 个独立调账码退役，调账单 `reasonCode` 直接落统一注册表的码；**原因码 + 文字 reason 成对必填**；Other 是正式码、reason 即手写内容。
5. **金库全线开单、CFO 复核**：调账四族 / 核销 / 认损 / 补单三路 / 挂起 / 事故登记全部只给金库，**不给运营任务**（覆盖 decisions 2026-09-02「运营查证定性→金库开单→CFO」三人链）。推单与一键重对账一并划给金库（业主未反对的连带假设，落地照此，异议再改）。自批死锁不存在：CFO 不持开单权。
6. **挂起 = 临时状态**：不影响之前给的处置方案——该格按钮原套保留、可覆盖重定（覆盖 + 各记审计）；行上挂着未走完的单才锁定（沿用现行同锚覆盖/挂单锁定）。
7. **死胡同修复带上**（BACKLOG「大额查不出定损后无出口」，2026-09-08 走查登记）：开认损/核销单的闸从「看定性出口」改为「看该行挂没挂已定损的事故」，金额锁定 = 定损额、不查小额线（事故流程即大额管控）。
8. **A1b 选甲**：SWAP 来源行不出冲正/冲销按钮（无兑换调账码，开不出单），只剩挂起；「兑换冲正码」记 BACKLOG，不为演示铺不到的场景立码。
9. **Case 列表页 ⚡场景气泡**：Disposition 列悬浮出「场景号 + 场景名 + 一句话说明 + 预期处置」，仅模拟模式（答案键驱动）；见 §7 与 L1。

## 2. 硬边界清单（六格 × 可选处置）

| 差异形状 × 池子 | 可选处置（行上按钮） |
|---|---|
| 金额不对 × 客户 | 冲正 ｜ 挂起·等下期 ｜ 挂起·调查中 |
| 金额不对 × 公司 | 补记 ｜ 冲销 ｜ 挂起两种 |
| 我有外无 × 客户 | 冲销 ｜ 改记 ｜ 挂起两种 |
| 我有外无 × 公司 | 冲销 ｜ 挂起两种 |
| 外有我无 × 客户 | 补单 ｜ 改记 ｜ 事故登记（未授权转出型）｜ 挂起两种 |
| 外有我无 × 公司 | 补记 ｜ 挂起两种 |

附加过滤（同为记账事实，非判断）：① SWAP 来源行不出冲正/冲销（§1-8）；② 补单弹窗内按账单行方向切——IN 行给「充值补录 / 出金退回认领」、OUT 行给「退汇认领」（方向守卫沿用现行）；③ 核销/认损**不进**此清单，仍是账龄到线后的后续动作（超期 + 挂起·调查中 + 小额线 + CFO 四道锁不动；事故来源见 §1-7 例外）；④ 在途行推单、已匹配行无按钮，均不变。

## 3. 行状态生命周期

全态样机见 artifact B1–B15，此处只记规则：

- **锁定一条**：行上挂未走完的单（调账 `adjustmentNo` / 补单 `supplementNo` / 划转）即锁定、按钮消失；驳回/撤回清锁、按钮组回来。
- **挂起两种的后事不同**：等下期 = 没毛病纯日切，下期自愈（活教材：REC20260908-007，Grace USDT，外部明细落对方下一业务日但余额已含，抵销桶开案 → 次轮 AUTO_HEALED）；调查中 = 有毛病没查清，是核销/认损/升级事故的入场券，3 天账龄倒计时照旧。
- 超期三岔口（公司小额→核销 / 客户小额→认损 / 大额→升级事故）、认损后待补款→补款、退汇余额不足→垫款，全部沿用现行链路，只换入口呈现。

## 4. 弹窗规格（M1–M12）

公共结构：证据区（只读）→ 原因码（只出该格 × 该处置对得上的码 + Other）→ 系统推导区（方向 / 金额 / 生效日，只读——算术不是判断）→ 查证说明必填 → 提交。要点：

- **M1 冲正**：码 = 记账金额错 / 银行费轧差 / 舍入差 / Other；金额 = |差额| 锁定，方向按差额符号（出账翻符号，沿用 `signedDeltaSign`）。
- **M2 冲销**：客户格码 = 重复入账（带双胞胎机器线索展示）/ 假信号 / 出款未执行 / Other；公司格码 = 公司记录错 / 公司多记 / Other；金额 = 整笔锁定。
- **M3 补记**：码 = 银行利息 / 银行杂费 / 公司少记（金额不对格）/ Other；方向按码或差额符号。
- **M4 改记**：码固定「记错客户」；对端候选 = **只扫打开中的案件**（同业务日 + 同资产 + 同客户池）取反向孤儿、金额完全相等（`listReattributionCandidates` 现行逻辑）；正主方加钱必填关联原单号；一张单牵两案。
- **M5–M7 补单**：一个「Supplement」按钮，弹窗按方向出类型；字段沿用现行组件（补录：链上来源地址 / 法币来源 IBAN；退汇/退回：候选原单单选，同钱包·成功·同金额）；退汇提交与批准各查一次余额，不足走垫款；M5 加一行提示「金额低于该资产单笔下限时，批准后停 OPERATION_PENDING，需在充值详情页放行」（BACKLOG №270 已知坑，不修只提示）。
- **M8/M9 挂起**：等下期码 = 跨账期（固定）；调查中码 = 归属排查中（仅外有我无×公司）/ 查无果·已穷尽 / Other；零账务不送审，提交即落定性 + 审计。
- **M10/M11 核销/认损**：锁定视图原样保留（四前提清单 + 金额锁定）。
- **M12 事故来源认损/核销（新）**：前提区换成「事故已定损（INCxxx · 定损额）」，金额锁定 = 定损额，小额线不适用；客户池出认损、公司池出核销；落账后调账单回挂事故页，走既有善后结案。

## 5. 单码制注册表（后端核心改动）

`cause-registry.ts` 与前端 `REASON_META` 两张表合一为**唯一注册表**，全系统一套词表：

- 成员 ≈ 24 码：现有 20 原因码 + `OTHER` + 三个单级专码（`CUSTOMER_REATTRIBUTION` / `UNEXPLAINED_WRITE_OFF` / `UNEXPLAINED_CLIENT_LOSS`——本来就一码一事，保留）。
- 每码字段：所属格（cells）｜label（菜单=手册=单据=审计四处同词）｜clue｜**允许的处置**（新，替代原 kind→出口判死）｜方向规则｜是否必须关联原单（边界线守卫沿用）｜客户面受控话术 customerLabel。
- 冲正/冲销/补记单据 `reasonCode` = 行级所选原因码 **1:1 直落**（合并安全依据：分录组合由「账簿 × 方向」定，**码不参与算账**）；改记/核销/认损单继续落专码。
- `resolveOutlet()`（成因判出口）退役，换 `dispositionsFor(rowFacts)`（按行事实算合法处置清单）；方向/金额派生函数（`signedDeltaSign`、`resolveWriteOff`）保留。
- `OTHER`：正式码，reason 手写必填；客户面话术走通用「Balance correction」，手写只进内部审计与单据备注（受控词表铁规不破）。
- 读侧兼容不做（数据可重铺）：种子、verify 脚本、对账读侧引用旧 11 码处全部换新码，一次收干净。

## 6. 后端其余改动面

- `disposition.service.record()`：入参从「成因（推出口）」改为「成因 + 财务所选处置」，仍写 `reconciliation_dispositions`（覆盖式、同锚、挂单锁定不变）；挂起路径由此一次落定性。动钱路径改为**弹窗提交时与开单原子落**（定性 + 单一次写，锚/回填/清锁机制沿用）。

- 审计：码不加不减；`RECON_DISPOSITION_RECORDED` 的 `outlet` 语义变为「财务所选处置」，`causeCode` 照录。
