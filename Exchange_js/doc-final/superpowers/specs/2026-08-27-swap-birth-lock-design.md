# 兑换出生锁设计稿（站3·需求变更批——业主 2026-08-27 口述裁定）

**缺口**：现状兑换下单后、合规通过前，客户卖出侧金额不上锁——同一笔钱可再发提现/兑换（防双花闸缺失）。提现是"下单即锁"，兑换不是，两域并排演示讲不圆。

## 圈的时刻表（业主裁定版）

| 时刻 | 动作 | 说明 |
|---|---|---|
| **下单**（报价执行落库同事务） | **画圈**：按腿 1（卖出腿）的记账条目、attempt=1 预占 | 锁 fromAmount 全额；手续费在买入侧扣，不在锁内。圈的编号=腿 1/第 1 次的确定性编号——后续落笔/擦圈天然对上 |
| 合规通过 → 结算开始（建腿 1） | **跳过画圈**（仅 legSeq=1 & attempt=1）| 出生已画过；单据照常铸出 |
| 腿 1 外部确认 | **落笔**出生圈（postLeg 原样，编号即中） | 腿 1 从此"圈跟单走"（提现型）；腿 2-4 原样"圈跟次走" |
| 腿 1 重试（attempt≥2） | 原引擎节拍：擦上次圈+画新圈 | 换座不解锁，保护不断档 |
| **KYT 拒绝落地** | **擦圈**退还余额 | 留痕携退还金额 |
| **FROZEN 落地**（两处：KYT 制裁冻单 / 批量冻单） | **擦圈**退还余额（业主裁定：终态不押钱，"每个终态必须回答钱去哪了"→回客户余额） | 押人靠限制账：制裁本人场景已冻人+连带冻他所有在途单；单冻只保全证据 |
| SUCCESS | 无新动作 | 圈早在腿 1 确认时落笔 |

**边界确认**：FROZEN 只可能发生在结算开始前（PROCESSING 中的单是停腿不冻单，避免半截账）——故拒绝/冻结两类擦圈永远只面对"腿 1/attempt 1"这一个圈，无歧义。

**留痕联动（β 词表随之）**：SWAP_CREATED 携锁定金额；SWAP_KYT_REJECTED / SWAP_FROZEN 携 releasedAmount。

**对照**：提现 FROZEN 持锁不擦——它有出口（解冻续付要用锁）；兑换 FROZEN 零出边终态，终态持锁违反公理。
