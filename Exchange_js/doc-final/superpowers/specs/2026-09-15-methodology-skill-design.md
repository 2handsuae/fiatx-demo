# Skill 设计：project-governance——多轮项目治理框架安装器

2026-09-15 ｜ 状态：设计稿，待业主评审 ｜ 最终产出物落 `~/.claude/skills/project-governance/`（个人 skill，不入本仓）

## 0. 一句话

把本仓长出来的工程方法论提炼成可复用 skill：项目启动（或中途补装）时**一次性安装**"治理骨架＋每个文件的生长规则＋回写泵"；具体内容（肉）不由 skill 提供，由项目在往后每一轮里用自己的事故和判例长出来。

## 1. 定位与边界判断

- **补哪层**：superpowers 管单轮任务的生命周期（脑暴→spec→plan→执行→评审），对轮与轮之间零主张——产物落哪、任务结束后什么留下、下一个失忆的会话怎么接班。本 skill 管的全是轮间。两者关系是引擎与底盘。
- **触发条件是"多轮"，不是"大型"**：判据是"会不会有很多个互相失忆的会话接力做这个项目"。三天写完不再动的大项目用不上；被几十个会话接力半年的小项目非有不可。
- **形态是一次性安装器**：装完后日常运转靠生成的项目文件自驱（收尾协议、checklist 用法、战役协议全写在生成物里），skill 不参与日常。理由：skill 的触发时机只有"开荒/补装"一个，指望它在每轮收尾被想起来不现实。
- **骨架/肉分界**（全篇的总纲）：凡"内容本身有用"的搬不走——铁律条文、禁做条目、评审判据内容、checklist 的行；凡"容器＋生长规则有用"的搬得走——路由表、三桶、表格式、判例库、泵。skill 只装后者；前者第一天靠种子访谈拍最小版本，之后逐轮生长。

## 2. Skill 文件结构

```
~/.claude/skills/project-governance/
├── SKILL.md                    # 流程：判断开荒/补装 → 种子访谈 → 生成骨架 → 自检
├── templates/
│   ├── claude-charter.md       # 项目总纲模板（§3 节清单）
│   ├── delivery-checklist.md   # 触发式清单空表 + 用法头
│   ├── review-rubric.md        # 评审规约模板（判据数封闭 + 判定表 + 出口）
│   ├── decisions.md            # 判例库头
│   ├── debt-buckets.md         # 三桶文件头（含各桶准入判据）
│   ├── campaign-charter.md     # 多波战役总纲模板
│   └── wave-spec-skeleton.md   # 波 spec 骨架（含空承接节）
└── references/
    └── methodology.md          # 每个构件的"为什么"＋本仓真实内容作肉样例（显式标注"样例非内容"）
```

- 模板与生成物一律**中文**（使用者是业主本人，工作语言中文）。
- 每个模板节附一小段本仓真实内容做样例，标注"这是 Exchange_js 的肉，不是你的内容"——空模板难抄，带样例好抄。
- skill 名暂定 `project-governance`；description 写清触发语："新项目立框架 / 装治理 / 建文档体系 / 项目开荒 / 中途补装治理"。

## 3. 安装物 A：项目总纲模板（生成 `CLAUDE.md` 或并入既有者）

结构对应本仓 CLAUDE.md，每节标注种子要求：

| 节 | 内容 | 种子要求 |
|---|---|---|
| §0 这是什么 | 项目定位一句 ＋ 观众/目的 | **需种子**（访谈问出） |
| §1 判断标准 | 两句话过滤器，任何任务先过它 | **需种子** |
| §2 禁做清单 | 点名列举、能 grep 的负面清单 | **需种子**（可以先短，两三条起步） |
| §3 允许的假设 | 理直气壮不防御的简化前提 | **需种子** |
| §4 出口 | 三桶表：发现什么放哪、什么规矩 | 骨架自带，桶名可调 |
| §5 铁律 | ≤6 条宗旨级，每条带"为什么"，落地写法外链 rules/ | **可空**，随轮长；上限写死防膨胀 |
| §6 流程尺寸 | 任务开场列做/不做 ｜ spec/plan 落点与归档 ｜ 战役协议（本文 §7） ｜ 派发分层槽位（本文 §8） | 派发分层**需种子**，余为骨架自带 |
| §7 闸门 | 两档结构：随手闸（每次改完跑）＋收尾闸（按触发条件叠加）；判据一律全绿；"测试的绿必须来自行为" | **需种子**（具体命令项目自己的） |
| §8 路由表 | 什么时机读什么文档 ＋ **封闭性规则**（不在表上、也没被表上文档链到的文档不该存在，发现即删或归档） | **需种子**（初版收编现有真实文档，不许放空表） |
| §9 收尾协议 | 每轮一行报告动了哪层 ＋ 回写泵（本文 §6） | 骨架自带 |
| §10 运维事实区 | 端口/命令/环境坑集中一处 | **可空** |

## 4. 安装物 B：文档目录骨架

```
docs/（根名可改，以路由表登记为准）
├── rules/
│   ├── delivery-checklist.md   # 空表起步
│   └── review-rubric.md        # 判据封闭模板
├── modules/                    # 真相层：现状唯一真相；overview.md 起步，按块拆篇（初拆由访谈问出）
├── acceptance/                 # 验收层：走查剧本 + 基线判据；形态由访谈问出（演示走查/测试套件/…），可后建，槽位先在路由表登记
├── decisions.md                # 判例库：只追加不改删；每条=日期｜决策｜为什么；已否决不翻案，推翻只能业主追加新条覆盖
├── BACKLOG.md                  # 桶①业务缺口：要读要做；收尾销账
├── PARKED.md                   # 桶②放下桶：**只许追加、不许读它找活干**
├── TOOLING-DEBT.md             # 桶③工具/环境债：要读要清
├── CHANGELOG.md                # 一合并一行
├── superpowers/{specs,plans,checkups}/   # 活产物
└── archive/{specs,plans,checkups,…}/     # 按来源分子目录
```

目录与桶名都可按项目改，语义不可改。桶②的命名规则：名字要能回答"这些东西什么时候才轮到"——本仓叫 PRODUCTION-NOTES 是因为它的范围边界是"生产化才需要"；别的项目按自己的边界起名（如 NOT-V1），默认 PARKED。

四条硬规矩随骨架安装：

1. **每个文件带三行头**：形状（这文件长什么样）｜谁写谁读（含"生成区不许手改"类标注）｜生长规则（什么事件触发往里写一条）。生长规则比初始内容重要——没有生长规则的文档三个月后还是空的或死的。
2. **每个桶带准入判据**（一句判定问句，如技术兜底桶的"攻击者？故障？并发？三个都不占不许进"）。理由：错桶比没桶危险——它给问题一个合法的藏身处（本仓 2026-08-31 错归事故为证）。
3. **checklist 空表带行模板与用法**：行=触发（动了什么）｜连带必做｜漏了出过什么事；用法=按左列扫、**裁剪权归 plan**（plan 时圈定"本任务过哪几条"并写死，收尾逐行销账；执行者无权临场省行）。没有事故背书的行不进表。
4. **归档协议**：spec / plan 随任务合并、由收尾会话移入 `archive/` 对应子目录。例外：战役总纲活到末波收官才归档；checkups 与其战役同生命周期。archive 入了不读，翻旧账走 git 历史或业主明示。

## 5. 种子提取访谈（开荒模式的核心交互）

种子只能从业主嘴里问出来，agent 不得代拍。访谈喂**两个安装物**（总纲的需种子节＋目录骨架的需种子件），逐题问、答一题填一处：

| 问题 | 喂哪里 |
|---|---|
| 这项目给谁用/看？什么算成功？ | 总纲 §0 / §1 判断标准 |
| 什么类别的工作在这个项目里理直气壮不做？ | 总纲 §2 禁做清单 |
| 哪些外部依赖或场景假装可靠/不存在？ | 总纲 §3 允许的假设 |
| 有没有第一天就知道的红线？ | 总纲 §5 铁律（答不上就空着，合法） |
| 现在有哪些检查/测试命令？ | 总纲 §7 随手闸 |
| 怎么算验收——给谁演示一遍，还是跑什么看什么？ | 验收层形态 ＋ 总纲 §7 收尾闸 |
| 这个项目大概分几大块？ | 真相层初拆 ＋ 总纲 §8 路由表 |
| 主会话用什么模型？额度上怎么打算？ | 总纲 §6 派发分层 |
| 现在已有哪些文档？ | 总纲 §8 路由表初版 |

答不上的节按表中"可空"处理；**需种子的节答不上不许编**——宁可业主给两句糙的，不要 agent 给一版像样的。

## 6. 回写泵（写进生成总纲 §9，框架不饿死的关键）

空框架放三个月还是空的；泵是把"做 10 轮就长出来了"变成现实的机制。四个回写时机：

1. **每轮收尾**：报一行动了哪层文档 ＋ CHANGELOG 一行 ＋ **销账**（本轮解决的 BACKLOG / TOOLING-DEBT 行划掉）＋ 过三问——这轮踩的坑要不要变成 checklist 新行？要不要落 decisions 判例？有没有该进桶的发现？
2. **评审/走查收尾**：判据外的发现一律落桶（各按准入判据），不进评审报告；真相层与验收层对不上的，登记 BACKLOG 一条。
3. **业主拍板时**（含否决与翻案）：当场落 decisions 一条（日期｜决策｜为什么）。判例库的主粮是拍板不是事故——脑暴和评审里裁掉的方案不落档，下个失忆会话就会把它重新论证一遍。
4. **事故归因后**：挑对的层落一条——判断力问题落总纲、连带遗漏落 checklist 行、方案取舍落 decisions——**必须带日期＋现象＋代价**（事故第三列是清单说服力的全部来源）。

## 7. 多波战役协议（写进生成总纲 §6，templates 带两份模板）

给"一个模块一波做不完"的场景，完整链条：

1. **体检前置**：开战役先摸底；扫描取数与判读分离（扫描可降档，判读不降档）。
2. **战役总纲**：目标／拆几波／每波边界与验收口径，单独一份，**活到最后一波**。
3. **每波 spec 只写细当前波**；下一波当场只立**骨架**（总纲链接＋空承接节＋已定事实＋待定岔口）。
4. **收尾只写承接记录**（实际偏差／新事实／下一波前提变没变），写进下一波 spec 开头；**不代写下一波 spec**——干完一轮的会话是给下一轮做设计的最差人选，满上下文里写出来的是没人讨论过的设计。下一波的展开是下一波新会话读总纲＋承接后跟业主脑暴的活。

## 8. 派发分层槽位＋证据交接合同（生成总纲 §6 内）

分界线：**怎么想的纪律在全局 CLAUDE.md（原则层，不动），怎么交接的合同在项目总纲（协议层，本 skill 装槽位）。**

- **派发分层槽位**（需种子）：本项目任务类型→模型档位的映射表；钉版本的写法（含 harness 坑，如 model 参数只收别名时改走省略字段继承）；降档的兜底条件（有没有终审接着）。理由：全局只有原则，映射表到每个项目必被改写（本仓即证据），且映射表会腐化，只能住项目层。
- **证据交接合同**（骨架自带，写死在体检/派发节）：扫描子代理只交「数字＋复现命令」、不交裸结论；否定性结论（零引用/没有/不存在）必附能复现它的搜索命令；主会话抽查复现后才采信。

## 9. superpowers 挂接（三处，写进生成总纲 §6）

1. **spec/plan 产物落点**重定向进项目文档区 `superpowers/{specs,plans}`（brainstorming 技能本身允许用户偏好覆盖默认路径），合并后入 archive/。
2. **plan 阶段**：Global Constraints 写两行引用 checklist（"通用清单全部适用＋本轮特有约束"），并扫左列圈定本任务触发哪几行、连同收尾核对表写死进 plan。
3. **收尾阶段**：逐行销账 ＋ 回写泵三问 ＋ §9 一行报告。

## 10. 中途补装路径（与开荒并列的第二入口）

已运行的项目补装，顺序不同：

1. 盘点现有文档（含散落的 TODO/待办/笔记）；
2. 建路由表，把还活着的文档收编进表；
3. 宣布封闭性：表外文档当场删或入 archive/；
4. 散落的"以后再说"按准入判据迁进三桶；
5. 种子访谈补齐总纲缺节（已运行项目多数种子已隐含在实践里，访谈变成"把你们已经在做的说出来"）；
6. 从下一轮任务起挂 plan 引用与回写泵。

## 11. 明确不装的（边界，防这个 skill 自己膨胀）

- **模型分层与证据纪律的原则层**（"我自己怎么想"的个人纪律）→ 不装，全局 CLAUDE.md 已有。注意协议层**不在此列**：映射表槽位与证据交接合同照本文 §8 装进生成总纲。
- **worktree 并行隔离** → superpowers 已有 using-git-worktrees。
- **一切肉**：铁律条文、禁做条目、评审判据的具体内容、checklist 的行——只在 references/ 里作标注过的样例出现。
- **单轮任务怎么跑** → superpowers 的地盘，不重复不改写。

## 12. 验收标准

1. **开荒演练**：在一个空目录走完 SKILL.md 流程（访谈可自问自答模拟业主），产出全套骨架；逐文件核查三行头齐全、需种子节非空、可空节确实空着。
2. **模板无悬空**：无 TBD/占位符；肉样例全部带"样例非内容"标注。
3. **反向检验**：用骨架清单对照本仓 doc-final 现状——本仓每个治理构件都能在骨架里找到对应槽位（骨架是从它抽的，不许丢件）；找不到槽位的构件，要么补槽位、要么在 §11 写明为什么不装。
