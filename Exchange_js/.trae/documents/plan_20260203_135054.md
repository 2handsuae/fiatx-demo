# 统一主体编号 (No) 字段及关联展示优化计划

## 1. 数据库模型更新 (Prisma Schema)
- 在 `prisma/schema.prisma` 中为以下模型添加唯一的 `No` 字段：
  - `User`: 添加 `userNo String @unique`
  - `CustomerMain`: 添加 `customerNo String @unique`
  - `Payin`: 添加 `payinNo String @unique`
  - `Payout`: 添加 `payoutNo String @unique`
  - `Clearing`: 添加 `clearingNo String @unique`
  - `Journal`: 添加 `journalNo String @unique`
- 统一生成规则前缀：
  - Customer: `CU`, User: `UR`, Payin: `PI`, Payout: `PO`, Clearing: `CL`, Journal: `JO`
  - 现有：Deposit: `DEP`, Swap: `SWP`, Withdraw: `WD` (更新自 `WDR`)

## 2. 后端逻辑更新 (Services)
- **通用生成器**: 统一使用 `generateReferenceNo` 工具函数。
- **创建逻辑**: 
  - 修改 `UsersService`, `CustomerAuthService`, `PayinsService`, `PayoutsService`, `ClearingsService`, `JournalsService` 的 `create` 方法，在创建时自动生成并填充 `No` 字段。
- **现有逻辑更新**:
  - 修改 `WithdrawTransactionsService` 将前缀从 `WDR-` 统一为 `WD`。

## 3. 数据迁移脚本
- 编写一个一次性脚本，为数据库中现有的存量数据（User, Customer, Payin 等）补全生成的 `No` 字段。

## 4. 后端 DTO & 返回值更新
- 更新对应的 DTO 定义，确保 API 返回结果中包含新添加的 `No` 字段。

## 5. 管理后台前端更新 (Admin Web)
- **列表页**: 在客户、用户、入金、出金、清分、记账凭证等列表页添加 "编号" (No) 列。
- **详情页**: 在详情页头部显著位置同时展示 "编号" 和 "ID"。
- **关联展示**: 
  - 在所有涉及主体关联的地方（例如：凭证关联的来源、钱包关联的所有者），不仅展示 UUID，同时展示其 `No` 字段，提高可读性。
  - 例如展示格式：`CU2305010001 (uuid-...)`。

## 6. 验证
- 运行 `npx prisma generate` 和 `npx prisma db push`。
- 启动项目并创建新主体，验证编号生成是否正确。
- 检查前端各个页面展示是否符合预期。
