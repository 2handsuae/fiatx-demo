# 清分中心模块实现计划

本项目将构建一套完整的清分中心模块，涵盖从规则模板定义到业务执行监控的全流程。我们将参考现有的“日记账模板”模式，确保 UI/UX 的一致性。

## 技术方案概览

### 1. 数据库模型 (Prisma)
在 `schema.prisma` 中新增四个核心模型，采用 **PascalCase** 命名模型，并通过 `@@map` 映射到数据库的复数蛇形命名（snake_case）：
- `ClearingTemplate` / `ClearingLineTemplate`: 规则定义层。
- `Clearing` / `ClearingLine`: 业务实例层（记录应收应付结构）。

### 2. 后端开发 (NestJS)
- **模块创建**: 新增 `ClearingModule`。
- **控制器 (Controllers)**:
    - `ClearingTemplatesController`: 处理抬头及行模板的 CRUD。
    - `ClearingsController`: 处理清分单据列表查询、详情查看及“重新清分”逻辑。
- **服务 (Services)**:
    - 实现基于事件驱动的清分引擎核心逻辑（MVP：模板直接计算金额）。
    - 关联 `payin/payout` 的回填机制。

### 3. 前端开发 (React + Tailwind)
- **菜单与路由**: 
    - 在 `DashboardLayout.tsx` 导航栏新增“清分中心”一级菜单。
    - 在 `App.tsx` 中注册相关业务路由。
- **列表页面实现**:
    - **清分抬头模板列表**: 参考 `JournalHeaderTemplateList.tsx`，支持状态切换、搜索和分页。
    - **清分管理 (Header)**: 展示清分主表，包含业务关联单据、状态监控及“重新清分”操作。
    - **清分明细 (Lines)**: 展示所有清分行，支持跨批次查询和金额筛选。

## 详细执行步骤

### 第一阶段：基础设施与后端核心
1. 修改 `schema.prisma` 并执行数据库迁移。
2. 生成最新的 Prisma Client。
3. 实现 `ClearingTemplate` 的后端 CRUD 接口及数据验证 (DTOs)。

### 第二阶段：清分业务逻辑与实例管理
1. 实现 `Clearing` 和 `ClearingLine` 的查询接口。
2. 编写“重新清分”逻辑：支持根据模板重新计算并覆盖现有清分行。

### 第三阶段：前端集成与 UI 开发
1. 更新 `DashboardLayout.tsx` 菜单结构，添加“清分中心”、“清分管理”、“清分明细”。
2. 开发 `ClearingTemplateList` 页面，实现模板的增删改查。
3. 开发 `ClearingList`（清分管理）和 `ClearingLineList`（清分明细）页面，对接后端接口。

### 第四阶段：验证与交付
1. 确保所有操作均有明确的反馈提示（成功/失败、加载状态）。
2. 进行基础的功能冒烟测试，确保分页、筛选和“重新清分”功能正常。
