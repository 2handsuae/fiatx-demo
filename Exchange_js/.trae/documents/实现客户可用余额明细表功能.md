# 实现客户可用余额明细功能

## 1. 后端功能实现 (NestJS)

### 1.1 定义查询 DTO
- 创建 `src/modules/journal-lines/dto/customer-balance-history.dto.ts`。
- 包含字段：`customerId` (必填), `assetId` (必填), `startDate`, `endDate`, `skip`, `take`。

### 1.2 扩展 JournalLinesService
- 实现 `getBalanceHistory` 方法。
- **逻辑细节**：
    1. 筛选条件：`accountCode = 'L.CLIENT_CREDIT'` (代表可用余额), `ownerId = customerId`, `assetId = assetId`。
    2. 计算“期初余额”：查询当前分页起始时间之前的所有相关流水金额之和（Credit 为加，Debit 为减）。
    3. 获取当前分页流水：按 `createdAt` 升序排列。
    4. 循环计算：基于期初余额，逐笔累加当前页流水的变动金额，生成 `postBalance`。
    5. 结果返回：将计算好余额的流水记录按时间倒序排列后返回给前端。

### 1.3 增加 API 接口
- 在 `JournalLinesController` 中增加 `GET /journal-lines/customer-balance-history` 接口。

## 2. 前端功能实现 (React)

### 2.1 创建明细页面
- 新建 `admin-web/src/pages/CustomerBalanceHistory.tsx`。
- **界面要素**：
    - **筛选器**：客户 ID 输入框/选择器、资产类型下拉框（USD, USDT, BTC 等）、时间范围选择。
    - **表格展示**：显示交易时间、类型（EventCode）、变动金额（正负数颜色区分）、交易后余额、关联单号（Source ID）。
    - **数字格式化**：金额显示千分位，并根据资产类型保留对应小数位。
    - **导出功能**：实现“导出 CSV”按钮，将当前筛选结果下载为文件。

### 2.2 配置路由与菜单
- 在 `admin-web/src/App.tsx` 中注册 `/ledger/balance-history` 路由。
- 在 `admin-web/src/components/DashboardLayout.tsx` 的“Ledger”一级菜单下增加“客户余额明细”二级菜单。
