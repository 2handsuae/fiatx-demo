## 项目改进计划：修复关键缺陷与工程化优化

基于前期的代码质量评估报告，我将执行以下改进措施，以提升系统的稳定性、可测试性和部署灵活性。

### 1. 修复前端运行时崩溃与配置优化
- **修复复制功能**: 在 `admin-web` 和 `client-web` 中创建统一的 `clipboard.ts` 工具函数，解决 `copyToClipboard` 未定义导致的崩溃问题。
- **消除硬编码 API 地址**: 
  - 引入环境变量 `.env` 管理 API 基础路径。
  - 批量替换前端代码中的 `http://localhost:3000` 为 `import.meta.env.VITE_API_URL`。

### 2. 修复后端自动化测试套件
- **完善测试依赖**: 针对 `AuthService`、`PayinsService` 等测试失败的文件，补全缺失的 `PrismaService`、`JwtService` 和 `EventEmitter` 等依赖注入。
- **修正测试逻辑**: 修复 `LiquidityConfigService` 测试中因状态机约束导致的更新失败。

### 3. 代码重构与抽象
- **统一编号生成逻辑**: 提取 `Swap` 和 `Deposit` 模块中重复的编号生成逻辑到公共工具类 `NoGenerator`。
- **减少冗余代码**: 清理不必要的类型转换（如多余的 `(this.prisma as any)`）。

### 4. 规范与性能优化
- **Lint 修复**: 批量执行 `npm run lint -- --fix`，并手动修复无法自动修正的变量未使用和 `any` 类型问题。
- **依赖管理**: 准备 Prisma 版本升级建议，并检查过时组件。

---
**提示**: 执行过程中将严格遵循不破坏现有业务逻辑的原则。完成后将重新运行测试套件验证改进效果。
