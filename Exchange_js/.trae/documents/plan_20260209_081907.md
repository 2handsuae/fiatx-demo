I will create a dedicated Clearing Line Detail page (`ClearingLineDetail.tsx`) and update the backend to support fetching a single clearing line with enriched fields.

### Plan Overview
1.  **Backend Update (`clearings.service.ts` / `clearing.controller.ts`)**:
    *   Currently, there is no endpoint to fetch a *single* clearing line by its ID (`GET /clearing-lines/:id`). The existing `findAllLines` fetches a list.
    *   I need to implement `findLineOne(id: string)` in `ClearingsService` (or a new `ClearingLinesService` if preferred, but keeping it in `ClearingsService` is simpler given the current structure).
    *   This method will:
        *   Fetch the line by ID.
        *   Include the parent `clearing` relation to get `clearingNo`.
        *   Manually populate `partyNo` (by looking up Customer/LP) and `assetNo` (by looking up Asset).
    *   Expose this method via a new controller endpoint (e.g., `GET /clearings/lines/:id`).

2.  **Frontend Update (`admin-web/src/pages`)**:
    *   **Create `ClearingLineDetail.tsx`**:
        *   Use the "Card Stack" layout (consistent with Customer/Journal/Clearing Detail).
        *   **Header**: Line No, Type badge, ID/Time metadata.
        *   **Row Identification**: ID, Clearing ID/No, Line No, Type.
        *   **Counterparty**: Party Type, Party ID, Party No.
        *   **Amount & Asset**: Asset ID, Asset Code, Amount.
        *   **Tracking**: Ref Type, Ref ID.
    *   **Update Routing (`App.tsx`)**: Add route `/clearing/lines/:id`.
    *   **Update List (`ClearingDetailsList.tsx`)**: Add "View Details" (eye icon) action to navigate to the new detail page.

### Implementation Details
*   **Backend**: Add `findLine` method to `ClearingsService` and endpoint to `ClearingsController`.
*   **Frontend**: Create new page component and register route.

This plan addresses the requirement to display a detailed view of a single clearing line with all the specified "No" fields populated.
