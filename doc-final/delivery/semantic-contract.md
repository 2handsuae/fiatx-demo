# 语义合同（Semantic Contract）

> **回答唯一的问题：重做这套系统时，什么必须分毫不差，什么随便发挥。**
> 本文件是交付包的宪法：条目只登记「保护对象 + 权威定义指针 + 允许/禁止判据 + 验证锚」，**不复制内容**——内容的真身在指针指向的 PRD 与代码里。
> **数值不进合同**：阈值、TTL、费率、限额是业务配置，调值走 PRD 变更记录，不算违约；合同防的是工程走样，不防业务变更。
> **改动纪律**：新模块→追加条目；**修改已有条目 = breaking change**，必须与产品当面对齐，不许静默改。

冻结基线：tag `delivery-2026-09-22`。PRD 文档集以 Lark 在线版为准（`doc-final/lark/` 有交付时留底）。

**触碰检查**（每轮需求变更时 30 秒过一遍，多数轮次四个全「否」）：
① 动了状态机 / 审计集 / 金额口径 / 业务键？→ 改本合同对应条目（敲锣打鼓）
② 又否掉一个方案？→ 追加进决策日志（`decisions.md`）
③ mock 转真或新增外部依赖？→ 更新依赖契约状态表
④ 新的平台级工程原则？→ 更新非功能底线
四文件的更新必须对应某篇 PRD 的变更记录行，互相引用。
