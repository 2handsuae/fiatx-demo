## 待定岔口（骨架级列出，波三 spec 脑暴先决）

2. **新幕编号**（总纲岔口⑤）：「公司的钱」（LP 兑换台 + 公司资金）入 `demo/script.md` 是新开一幕（如第九幕）还是并入既有幕（如并入第一幕"开业"或独立小节）？波三收官随剧本统一定，参照甲波五先例（甲的场景 19-25 收官时一次性定稿为"第八幕"）。
3. **穿底补救主线的具体走查步骤**：⚡托管失窃事件 → 事件定损 → 注资单补运营户 → 补款划转进客户池——四个环节涉及三个既有主体（事件中心/注资单/内部划转单），波三 spec 需要把每一步的账号切换、审批链、账本分录逐帧钉死（照场景 26/28/29 的详细程度），不能只写"串联既有件"一句话带过。
4. **跌破接电的具体触发条件与事件类型**：水位跌破阈值 → `PRUDENTIAL_BREACH` 事件（甲已建类型）→ 报送工单——是看板端主动轮询触发，还是某个操作动作（如金库查看看板）触发写检查？触发时机与"零事件、零推送"的波二假设①（承袭甲假设④）如何兼容，波三 spec 定。
5. **decisions.md 三条一并落笔的具体措辞**：F_LIQ 复活翻案（含 COA v2 局部取代声明）、LP 三拍板、⑰甲案 + B1/B2 两分——总纲 §7 第 5 条已列清单，波三收官会话直接写，不需要脑暴，只需要收集波一波二两批的准确细节（本骨架 + 波一骨架已备齐）。
